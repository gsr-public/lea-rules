# Framework Mappings

This file lists, for every framework tag used in this repository, which rules carry it. It is generated from the `tags` field of the rule files under `rules/`.

Mappings are informative. They show which control objective a technical check provides evidence for; they are not an official CIS Benchmark, an audit opinion, or a certification. A control is usually satisfied by a combination of technical settings, processes and documentation, and a passing rule covers only the technical part it describes.

Notes:

- `std:CIS_Controls_v8:<n>` refers to CIS Critical Security Controls v8 safeguards, not CIS Benchmark section numbers. Every rule with a safeguard tag also carries the generic `std:CIS` tag.
- `std:ISO27001:` tags use ISO/IEC 27001:2022 Annex A identifiers (for example `A.8.9`). Some rules exported from the LEA production set also keep their original ISO/IEC 27001:2013 identifiers (for example `A.9.2.3`).
- `std:CMMC:` tags use CMMC 2.0 Level 2 practice identifiers (NIST SP 800-171 Rev. 2 numbering).
- `std:NIS2:Art21.2(x)` refers to the measure letters in NIS2 Directive (EU) 2022/2555, Article 21(2).
- `std:DORA:Art9` (protection and prevention) and `std:DORA:Art10` (detection) refer to Regulation (EU) 2022/2554.
